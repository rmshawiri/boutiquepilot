# Checklist Play Console — chantier de publication séparé

Application Android Bêta 4 validée fonctionnellement par le propriétaire. Aucune approbation ni publication Google Play. Les décisions ci-dessous ne sont pas remplies automatiquement.

1. Créer/sélectionner BoutiquePilot dans le bon compte développeur ; vérifier le package com.morashawiri.boutiquepilot et les droits administrateur.
2. Langue principale : français proposé ; type : Application. Choix gratuit/payant : décision du propriétaire, à arrêter avant diffusion. Catégorie proposée : Business / Professionnel.
3. Coordonnées support : boutiquepilot@morashawiri.com ; site : https://boutiquepilot.morashawiri.com/. Compléter uniquement les coordonnées administratives officielles exigées ; ne rien inventer.
4. Approuver le texte de confidentialité Android et les pratiques de support, puis déployer sa page publique, vérifier HTTPS/URL et l’accès depuis l’application. Bêta 4 ne contient actuellement aucun écran/lien dédié à cette politique : si un ajout embarqué est requis avant soumission, il faudra une versionCode > 4 ; ce changement ne doit pas être masqué comme une modification documentaire.
5. Data Safety : relire les définitions Play et les faits de 10-confidentialite-et-play.md. Pas de transmission automatique détectée dans cette version ; faire confirmer les réponses par le propriétaire.
6. Publicité : aucune intégrée. Accès à l’application : sans compte, sans connexion, données de démonstration ; fournir au reviewer les étapes d’ouverture et de navigation.
7. Public cible/tranches d’âge : décision propriétaire. Remplir la classification du contenu réelle, sans présumer une note IARC.
8. Fonctionnalités financières : expliquer la tenue locale de caisse/télécom, sans exécution de paiements ou transferts. Faire valider les réponses au questionnaire affiché.
9. Compte : aucune création de compte dans cette version ; expliquer l’effacement des données locales et les sauvegardes exportées, sans promettre leur suppression chez un tiers.
10. Importer icône 512 × 512, feature graphic 1024 × 500 et les quatre captures Android réelles contrôlées. Ne pas importer les modèles d’affiches ou une capture navigateur.
11. Relire nom, descriptions courte/complète, notes de version et coordonnées de 09-fiche-google-play.md.
12. Avant toute diffusion, configurer la continuité de signature selon 14-play-app-signing.md. Ne pas accepter une nouvelle clé de signature sans décision explicite.
13. Préparer la release sur le canal choisi, vérifier AAB/versionCode/certificat et résultats des contrôles Play. Le fichier actuellement préparé est 1.0.0-beta.4 / 4 ; toute modification binaire impose une version supérieure.
14. Vérifier les tests éventuellement imposés au compte, les accès production et les retours de pré-lancement. Choisir les pays, la diffusion, les coordonnées et les éventuelles déclarations fiscales/administratives avec le propriétaire.
15. Vérifier la politique publique, l’installation et les mises à jour depuis le canal Play retenu, puis obtenir l’autorisation explicite avant publication.

Sources officielles : https://support.google.com/googleplay/android-developer/answer/9859455 ; https://support.google.com/googleplay/android-developer/answer/10144311 ; https://support.google.com/googleplay/android-developer/answer/14151465 . Recontrôler au jour de la soumission.
